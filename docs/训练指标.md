# 训练指标

本项目自己训出来的指标。与 `backend/app/services/tdx/indicators/` 下的 TDX 移植指标
区分开：那些是现成公式，这些是从数据里学出来的。

> **定位：动能参考，不是买卖决策依据。**
> 最强的 v5 胜率 62.1%，一年只有约 7.5 次机会。常用的 v4 是 58.3%。
> ⚠️ 2026-09-05 修正: 原先标称的 76.2% / 63.7% 是**前视造成的**，见第三章。
> 它们的作用是把候选池从几千只缩到几十只，不是告诉你买哪只。**所有胜率都基于 H=20 持有期，不适用于短线。**

## 二、每个指标的来历

### 买卖很准 v3 — 超卖反转 + 噪声过滤

**原信号**：`compute_lines` 的买线从 >0 回落到 0（连续超卖状态刚结束）。

**先测 baseline，结论是它本身没有 alpha**：32 万个买点 vs 同期随机对照，
短周期（3–5 天）**输给随机**（−0.006pp），20–40 天才微弱跑赢（+0.2~0.37pp），
胜率 48.6~50.7%，中位数多为负。**均值为正几乎全来自市场 beta。**

这解释了 v2 那次 MCPT p=1.0：不是过滤规则不行，**是被过滤的东西本身就是噪声**。

**v3 的做法**：标签用【同日 × 同波动五分层】内的超额，断掉"挑高波动"的作弊路径。
（v2 失败正因标签只按同日中性化，模型学成了波动率筛子：九宫格分层内 6/9 为负。）

**结果**：胜率 48.9→50.9%，中位 −0.074%→+0.200%，波动层内三档超出全为正。
按天 t=1.39，**仍不显著**。

**持有期 H=20**（2026-09-05 修正，原为 10）。实测扫描：

```
H=5   +1.6pp  t=1.86
H=10  +2.0pp  t=1.35   ← 原设置，是拍脑袋定的
H=20  +2.4pp  t=4.07   ← 现设置
H=40  +1.4pp  t=7.35
```

### 主力吸筹 — 筹码换手痕迹

**目标**：未来 10 日内出现【单日涨幅 >7% 且 量 >20 日均量 2 倍】。价量齐升才算拉升。

**先证伪了两个流行说法**（纯价量维度）：

- 「缩量横盘蓄势」**是错的**：横盘天数最多的 10%，拉升概率仅 **2.87%**（基础 8.30%）
- 「波动压缩后突破」**也反向**：波动最压缩一档 7.73%，波动最大一档 10.90%
- 真正预示拉升的是"**已经在动**" —— 纯价量做不到"提前"，只能"跟随早期"

**突破口是筹码分布**（tushare `cyq_perf`，2018-01 起，950 万行）。有效的**只有获利盘族**：

| 特征 | Q10/Q1 |
|---|---|
| 获利盘变化20 | 2.24 |
| **获利盘背离** = 获利盘变化 − 价格涨幅 | **2.16** |
| ★量能萎缩（价量最强，对照） | 1.70 |
| 筹码集中度 | 1.10 ❌ |
| 低位筹码占比 | 1.01 ❌ |

**「筹码集中度」完全无效**，这推翻了我原本的假设。吸筹不一定让筹码变集中，
但一定会改变**获利盘结构**：价格没动而获利盘上升 = 有人在低位持续接走浮筹。

**增量检验**：价格位置×量能 双重控制的 3×3 九宫格，九格 Q10/Q1 全为正、最小 1.63，
控制前后几乎不衰减（2.16→2.09）→ 筹码携带的是价格和成交量里**没有**的信息。

**样本外**：Q10/Q1 = 4.81，按天 t = 77.4，逐年八年 1.70~2.02 倍无失效。

⚠️ **它单独用是负面的**（H=20 胜率 43.5%、中位 −2.06%）——因为它预测"会不会拉升"，
而拉升前的票往往还在跌。**但它是 v4 最大的增益来源。**

### 低点组合 v2 — 阶段底部 + 过滤

原指标有两类买入信号，实测差异很大：

```
阶段底部(动力线上穿0.2)          H=20 超出随机 +0.557pp  胜率 51.8%  ← 采用
DIBU(13/21/34/55四周期KDJ全<20)  H=5  【输给随机】-0.074pp        ← 弃用
```

**条件更苛刻的 DIBU 反而更差** —— 深度超卖多出现在下跌趋势中段，接的是下落的刀。

**结果**：Top10% 胜率 53.8→57.7%，按天 **t=3.88**（第一个超过 3 的），
波动层内三档 t 全部 >2.5（2.55/2.80/3.74）。

**2026-09-06 补测 —— 原指标其实有 6 个信号，当初只测了 2 个**：
买入侧还有「阶段关注」(动力线上穿 0.5)，卖出侧有 TOBU / 清仓 / 短线卖出。
补测「阶段关注」并顺带扫了阈值（1670 只抽样，H=20，vs 同日全市场）：

```
上穿 0.05     551 个   胜率 57.5%   超出 +4.31pp
上穿 0.10   4,185 个   胜率 59.4%   超出 +1.59pp
上穿 0.15  13,362 个   胜率 56.7%   超出 +1.03pp
上穿 0.20  26,080 个   胜率 54.6%   超出 +0.79pp   ← 现用(阶段底部)
上穿 0.30  52,082 个   胜率 52.2%   超出 +0.38pp
上穿 0.50  82,521 个   胜率 50.6%   超出 +0.16pp   ← 阶段关注, 基本没用
```

**干净的单调剂量反应**——阈值越低越强，这种形状通常说明是真效应而非噪声。
漏掉的「阶段关注」本身很弱，但它带出的阈值曲线说明 **0.10 可能比现用的 0.20 更好**
（胜率 59.4% vs 54.6%，信号量仍有约 1600 个/年）。
⚠️ 这只是原始信号对比，**还没过波动×市值九宫格**，不能直接换。

**跨指标发现**：`筹码宽度` 在本指标里重要性第一（0.130），但在主力吸筹里完全无效
（Q10/Q1=1.10）。**筹码数据源通用，但具体哪个特征有效必须按目标重新筛。**

### 买卖很准 v4 — 共振

**v3 强档（rank≥0.8）与 主力吸筹强档（rank≥0.95）在 ±3 交易日内同时触发。**

不要求同一天：两个指标描述的是同一段行情的不同阶段，触发时点天然错开，
严格同日会漏掉绝大多数真共振。

**三关验证全过**：

```
关1 逐年：2019-2026 八年全部 >54%（最低 2026 年 54.4%）
关2 随机对照：62.5% vs 同日随机 53.2%±0.42，z=22.1
关3 波动×市值九宫格：九格胜率超出全为正，均值 +15.5pp，最小 +11.1pp
```

### 买卖很准 v3.5 — 参数重扫（2026-09-05 已下架）

移植 TDX 时照抄的参数 `MA5/LLV10/连续5`，从没针对 A 股验证过。
36 组网格扫描（MA∈3/5/8 × LLV∈5/10/15/20 × 连续∈3/5/10）后，**它只排 9/33**。

```
全市场 (H=20, vs 同期随机对照)
原参数 MA5/LLV10/5   28.1万信号  胜率 50.9%  超出 +0.190pp
最早   MA3/LLV15/3   35.5万信号  胜率 50.4%  超出 +0.242pp
最准   MA8/LLV20/10   9.5万信号  胜率 56.2%  超出 +0.602pp  ← v3.5 采用
```

**原参数两头不靠**：既不够早，也不够准。

⚠️ **v3.5 是"放大器"**：好年份 +1.0pp、坏年份 −1.0pp（原参数只有 ±0.5pp），
2020/2023/2025 三年跑输随机 —— **普涨行情里严格筛选反而错过**。这是"严格"本身的
固有属性，调参消除不掉。

→ 推论：**库里其他 TDX 移植指标的参数，可能都值得重扫一遍。**

**下架原因（2026-09-05）**：实际用下来没有比 v3 更好。它统计上确实更准（56.2% vs 50.9%，
超出随机 +0.602pp vs +0.190pp），但代价是信号少三分之二、普涨行情跑输、作为共振材料
也比 v3 差。**另外它压根没接进每日增量**（`update_indicators.py` 只跑 v3/吸筹/低点），
数据停在建表那天，再放下去只会变成一个悄悄过期的指标。

表 `maimai35_signal` 和 `build_maimai35.py` 保留，随时可以接回来。

### v5 — 三重共振（叠加龙虎榜）

`v4` 再叠一层「近 5 日龙虎榜机构净买入 > 0」。

龙虎榜（`top_list`，13 万条）**覆盖率仅 1.2%**（只有异动才上榜），单独用没意义，
但作为第三层过滤：

```
v4  (v3强 × 吸筹强)          n=2,157  胜率 58.3%  收益 +5.57%  1.2个/天
v5  (+ 龙虎榜机构净买入)      n=   58  胜率 62.1%  收益 +6.86%  7.5个/年
(以上为修正后的因果口径; 修正前含前视的数字见第三章)
```

**关键验证 —— 同等涨幅下对比**（排除"异动本身"，因为上榜的票当天本来就在动）：

| 当日涨幅 | 上榜拉升率 | 未上榜 | 差额 |
|---|---|---|---|
| **−2~2%** | 12.21% | 7.26% | **+4.95pp** |
| >9% | 33.21% | 27.18% | +6.03pp |
| 5~9% | 13.57% | 14.37% | −0.80pp |

**「−2~2%」那一档最有价值**：价格几乎没动却上了龙虎榜 = 大资金在换手但价格没反应。
**与「获利盘背离」同一逻辑**，只是这里是实名席位的硬记录，不是从价格反推的。

机构净买入分五档：Q1净卖 14.93% → Q4 **28.63%** → Q5净买 25.20%
—— **不是越多越好**，极端净买入反而回落（可能是游资对倒或已拉过高）。

⚠️ **0.3 个/天 ≈ 三天一次，一年 70 次。不是选股工具，是"出现时必须认真看"的提醒。**

### 一个反直觉发现：更准的基底 ≠ 更好的共振材料

```
v3   单独 50.9% → 与吸筹共振 58.3%  (1.2个/天)
v3.5 单独 56.2% → 与吸筹共振 57.1%  (0.4个/天)
```

v3.5 单独更强，共振后反而更弱。**共振需要的是足够的信号量 + 独立的误报模式，
而不是单个指标的精度** —— 信号本来就少，再取交集就所剩无几，统计上也更不稳。

## 三、这轮最重要的方法论结论

### 0. 从 50.9% 到 62.1% 的完整路径

```
v3   胜率 50.9%   ← 起点
 ├─ 堆 14 个新特征(筹码+市场状态)  → +0.0pp   ❌ 完全没用
 ├─ 持有期 H=10 → H=20            → t 1.35→6.48  ✅
 ├─ 原指标参数重扫 (v3.5)          → +5.3pp   ✅
 ├─ × 主力吸筹共振 (v4)            → +7.4pp   ✅✅
 └─ × 龙虎榜机构净买入 (v5)        → +11.2pp  ✅✅ (但一年只有 7.5 次)
```

(上面是因果口径。含前视时这两步分别是 +12.8pp 和 +25.3pp —— 差额就是偷看未来的部分。)

**最直觉的那条路（堆特征）贡献是 0。** 真正有效的三件事：
**调对持有期、扫对参数、跟独立信号共振。**

### 3. 共振的时间窗只能向后看 —— 一次前视事故

v4/v5 的共振原本写成 `pp.trade_date between mm.trade_date - 5 and mm.trade_date + 5`、
`lb.trade_date between mm.trade_date - 7 and mm.trade_date + 7`。

**这是前视。** T 日的信号要求知道未来 5~7 天会不会出现吸筹信号、会不会上龙虎榜,
而龙虎榜是事后才公布的。当时想的是"两个指标描述同一段行情的不同阶段, 触发时点
天然错开", 这个想法本身没错 —— 错在**错开的方向只能是过去**。

改成只向后看之后:

| 口径 | 信号数 | 胜率 | 均收益 | 超同日全市场 |
|---|---|---|---|---|
| v4 前视 | 5,882 | 64.6% | +7.98% | +5.34pp |
| **v4 因果** | 2,157 | **58.3%** | +5.57% | **+1.93pp** |
| v5 前视 | 609 | 78.0% | +19.30% | +16.73pp |
| **v5 因果** | **58** | **62.1%** | +6.86% | **+2.49pp** |

**v5 有九成的信号是靠未来才成立的。** 7.7 年只剩 58 个, 样本量已经小到没法下结论。

教训: 之前那套验证规矩(随机对照、九宫格、逐年、截断重算)全都跑过了, **但它们
检查的是"信号和收益的关系", 没有一条检查"信号本身是什么时候能知道的"**。
所以第 6 条的截断重算要扩展 —— 不只重算指标值, 还要重算**共振/join 的结果**。

### 1. 堆特征救不了坏基底

给 v3 加了 8 个筹码特征 + 6 个市场状态特征，H=10 下还是 **+2.0pp，和原来一模一样**。
因为买卖很准的原信号 vs 随机 ≈ 0，**从噪声里能挖的东西有上限**。

真正有效的是另外两件事：**调持有期**（t 从 1.35→4.07）和**共振**。

### 2. 单独没用的信号，可能是最好的过滤器

主力吸筹单独用胜率只有 43.5%（低于基准 49%），但叠加到 v3 上把它从 50.9% 抬到 62.5%。
**因为两者误报模式不同，共振能互相抵消噪声。**

→ 以后训出新指标，**第一件该做的是测它和现有指标的共振**，而不是单独看它多强。

## 四、测过但不用的

拉了数据、跑了验证、结论是不用。记在这里是为了不再重做一遍。

### 机构席位 top_inst —— 数据不够, 无法评估

龙虎榜的席位明细, 想把 v5 的「净买入」细化成「是不是机构专用席位」。

```
覆盖 2018-01 ~ 2019-08(只拉了个开头, 35.7 万行)
落到 v4 信号上: n=13
```

13 个样本什么都测不出来。而且它**没有近期数据, 实盘跟不了** —— 与北向资金停更
同一类问题。要用得重拉七年, 而现在的 `net_amount`(全量)在 v5 里已经工作得很好。

### 股东户数 holdernum —— 数据完整, 但信号是假的

「户数下降 = 筹码集中 = 有人吸筹」, 15.8 万条季度数据, 覆盖 2016 至今。
⚠️ 必须用 **ann_date(公告日)** 而不是 end_date 匹配, 否则是前视。

```
v4 基底                       n=5,882  胜率 64.6%
  + 户数下降(原始)             n=1,316  胜率 65.5%   看似 +0.9pp
  + 截面排名 降最多 20%         n=  614  胜率 65.1%
  + 截面排名 升最多 20%(对照)   n=  607  胜率 66.2%   ← 对照组反而最高
```

**对照组比实验组还好**, 那 +0.9pp 是噪声。而且 59.1% 的季度都在下降(注册制
扩容下的普遍趋势), 原始「下降」本身没有区分度。

另有个结构性问题: **季度披露、滞后一到三个月**, 而 v4/v5 是日频信号。拿两个月前
的快照过滤今天的信号, 时效对不上。

## 六、验证规矩（每个指标都走完这套）

1. **先测原信号 baseline vs 同期随机对照** —— 不先做这步，等于不知道过滤器在过滤什么
2. **标签按【同日 × 同波动层】中性化** —— 否则模型学成波动率筛子
3. **walk-forward 逐年重训** —— 每个测试点都是真样本外
4. **按天聚合算 t** —— 用信号数当样本量会让 t 虚高 4 倍以上（同一天的信号高度相关）
5. **波动×市值九宫格层内验证** —— 排除"只是挑高波动小市值"
6. **截断重算查前视** —— 把数据砍到 T 日重算，值必须与全量一致。
   ⚠️ 多表 join / 共振类信号必须连 join 结果一起重算 —— 单个指标值没问题，
   不代表组合信号没问题（v4/v5 的前视就是这么漏掉的）。
7. **每个 join 的时间窗都要问"这个数据 T 日收盘时公布了吗"** —— 龙虎榜是盘后
   公布的，窗口用 `T-7 ~ T` 可以，写成 `T-7 ~ T+7` 就是偷看未来。
8. **基准价必须是你真正能买到的价** —— 与第 7 条是两回事。盘后才知道的信号，
   时序上没偷看，但拿 `close[T]` 当买入价仍然错，你最早只能 T+1 开盘买。
   实测「10日涨10%」：龙虎榜的票次日平均高开 **1.31%**，命中率从 41.53% 掉到
   **37.22%**（高估 4.31pp）；而 v3/吸筹/低点这类盘中就能算出来的信号跳空仅
   ±0.03%，几乎无差别。**判断标准：信号是"盘中能算"还是"盘后才公布"。**

## 七、踩过的坑

- **重写已有实现**：为向量化重写 `compute_lines`，`min_periods` 处理不同 → 648 天里
  59 天买线值不一致，漏掉 42% 信号。**凡涉及已有实现一律复用，不重写。**
- **时区**：后端 `calendar.timegm` 生成的 timestamp 是 UTC 基准，前端用
  `setHours(0,0,0,0)` 归一化会整体偏移一天 → 标记早一根 K。**统一用 UTC 日期字符串对齐。**
- **数据覆盖率**：收盘后 K 线渐进入库，最新交易日常只有三分之一成分股到位
  （实测 13/34）。板块均值因此严重失真 → 加了 80% 覆盖率阈值。
- **`/app/fable` 非挂载目录**：容器重建即丢失。研究数据一律放 `/app/data/research/`。
- **构建失败静默沿用旧镜像**：`docker compose up --build` 构建失败仍返回 0。
  **部署后必须验证打包产物含新代码。**
- **三个页面用不同组件**：`ChartArea`(行情/选股) / `LiveView`(实时) / `SectorView`(板块)。
  给其中一个加功能，另外两个**不会自动有**。一天之内因此漏了五次
  （板块条漏两个页面、v4 切换漏两个页面、副图参数、CSS 路径、时区）。
  **凡是改指标菜单或图表叠加，必须三处都过一遍。**
- **`git checkout` 不是撤销键**: 未提交的改动用它回退, 直接没了, 不可恢复
  (2026-09-05 清掉了 MainChart.tsx 一整天的训练指标接线, 只能重写)。
  想撤销刚才的编辑就改回去, 不要动 git。
- **改完要在浏览器里等数据真到位再看**: 标记类改动截图太早会看到"没画出来",
  容易把渲染问题误判成数据问题(v3.5 就这么误诊过一次)。
- **if-else 链没有 default 保护**：切换逻辑写成
  `n==="pump" ? A : n==="didian" ? B : C`，新增第四个选项时会掉进兜底分支 C，
  静默切换了错误的东西且不报错。**行情页用数组 toggle
  (`prev.includes(n) ? 移除 : 添加`)，天然没有这个问题** —— 应该统一成这种写法。
